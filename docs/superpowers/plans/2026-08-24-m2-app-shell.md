# M2 App Shell Implementation Plan

**Goal:** A macOS window that drives a real crawl and browses its results live —
toolbar, sidebar, report tabs, paged table, detail inspector.

**Spec:** `docs/superpowers/specs/2026-08-17-screaming-koda-design.md`, sections
"The window" and "Crawl engine".

## Architecture

Three targets, layered so that almost nothing that matters lives in a view:

| Target | Imports | Holds |
|---|---|---|
| `KodaCore` | Foundation, GRDB, SwiftSoup | Crawl and queries. Never AppKit or SwiftUI. |
| `KodaUI` | KodaCore, Observation | Observable models: crawl control, table paging, selection. No AppKit or SwiftUI. |
| `KodaApp` | KodaUI, SwiftUI, AppKit | Views only. |

`KodaUI` exists so the interesting logic is testable headlessly. A view model that
imports SwiftUI cannot be tested under Command Line Tools, and a paged table with
an LRU cache is exactly the kind of thing that needs tests.

## Verified constraints

- SwiftUI, AppKit, Observation and `NSViewRepresentable` are all present in the
  Command Line Tools SDK and link under SwiftPM. Verified before planning.
- There is still no XCTest or Testing in the CLT SDK, so `KodaUI` is tested
  through the existing swift-testing dependency and `KodaApp` is not unit tested.
  Views stay thin enough that this is an acceptable trade.

## Global constraints

- **`KodaCore` must never import AppKit or SwiftUI.** `KodaUI` must not either.
- **Pause is stop.** The frontier is in SQLite, so stopping after the current
  chunk and starting again is a resume. Inventing a separate paused state would
  add a way for the database and the engine to disagree.
- **Sorting and filtering are SQL**, not Swift. Re-query; never sort a full
  result set in memory.
- **Column identifiers come from the report definition**, never from user text,
  so a sort or filter cannot become an injection.
- Commit after every task.

---

### Task 1: Cooperative stop in the crawl engine

Pause, and quitting mid-crawl, both need the engine to stop between chunks
without corrupting the frontier.

- Produces: `CrawlEngine.requestStop()`, `CrawlEngine.isStopped`, and `run`
  returning early with in-flight URLs left claimed for `resetInFlight` to recover.
- Tests: stop mid-crawl leaves the frontier resumable; a stopped crawl completes
  on a second run; stop before start is a no-op.

### Task 2: Paged, sorted, filtered report access

- Produces: `ReportQuery` (definition + sort column + direction + filter text),
  `Store.rows(for:limit:offset:)`, `Store.count(for:)`.
- Sort and filter wrap the report SQL in an outer SELECT so no report definition
  needs to know about them.
- Tests: paging returns disjoint slices covering the whole set; sorting by each
  column; filter narrows and is case-insensitive; a filter with `%`, `_` or a
  quote is matched literally rather than as a wildcard or an injection.

### Task 3: URL detail queries

- Produces: `Store.urlDetail(id:)`, `.inlinks(to:)`, `.outlinks(from:)`,
  `.images(on:)`, `.hreflang(on:)`.
- Tests: over a crawled fixture, each returns what the link graph implies.

### Task 4: KodaUI observable models

- `RowWindowCache` — fixed-size windows over a `ReportQuery`, LRU eviction, so
  the full row set is never resident.
- `ReportTableModel` — row count, row access, sort and filter mutation, refresh.
- `CrawlController` — start, stop, resume, live progress, current phase.
- `AppModel` — open database, report selection, row selection, throttled refresh.
- Tests: cache evicts and never exceeds its window budget; a cache miss loads
  exactly one window; changing sort or filter invalidates; controller
  transitions; refresh throttling.

### Task 5: KodaApp views

- `KodaApp` — window, `.commands`, open and new-crawl.
- `ToolbarView` — URL field, Start/Stop, live counts.
- `SidebarView` — groups and reports with counts.
- `ReportTableView` — `NSViewRepresentable` over `NSTableView`, paged data source.
- `InspectorView` — details, inlinks, outlinks, images for the selected URL.

### Task 6: `.app` bundle script

SwiftPM produces a bare executable. A window app needs a bundle with an
`Info.plist` to get a Dock icon, a menu bar and focus.

- Produces: `Scripts/build-app.sh` writing `ScreamingKoda.app`.

## Completion criteria

- `swift build` and `swift test` pass, no warnings.
- `KodaCore` and `KodaUI` import neither AppKit nor SwiftUI.
- `Scripts/build-app.sh` produces a launchable bundle.
